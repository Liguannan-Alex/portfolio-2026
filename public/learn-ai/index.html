入门

基础概念 · 易混淆词辨析

这一节的词天天出现在 AI 讨论里，但经常被混用。先把这十组概念分清，后面看每一层都不会晕。

API vs 工具（Function Calling）

两个方向完全相反的调用。API = 你调模型：你的程序向模型服务接口发请求（比如 OpenAI 的 chat/completions），它返回一段文字，模型本身碰不到外部世界。工具 = 模型调你：模型判断需要帮助（查天气、读数据库、订机票）时，输出一条结构化的"调用申请"，你的程序去执行，再把结果喂回给模型。Function Calling 是这套机制的名字，MCP 是正在成为行业标准的接口规范。一句话记住：API 是"人用模型"，工具是"模型用外部能力"。

训练 vs 推理

训练是上学：读海量数据、反复调整几十亿上千亿参数，产出是模型文件，烧算力、花数百万美元、只发生一次。推理是上班：加载训好的模型，为用户请求一个字一个字生成回答，7×24 持续进行、成本按 token 计。业界说"训练芯片/推理芯片""训练集群/推理服务"，分的就是这两件事。

模型权重 vs 推理引擎

训练产出的模型只是一堆数字（权重文件，如 .gguf / .safetensors），自己不会跑。要它生成文字，需要推理引擎把权重加载进显存、管理 KV 缓存、调度计算——llama.cpp、vLLM、Ollama 都是引擎。关系类似游戏光盘和游戏机：同一个模型（光盘）可以装在不同引擎（主机）上，引擎决定跑多快、在哪跑。

聊天机器人 vs 工作流 vs Agent

三种 AI 应用的自主性阶梯。聊天机器人：你问一句它答一句。工作流：步骤预先画死（先检索→再总结→再排版），模型只在每个节点填空，稳定可控。Agent：只给目标，它自己拆任务、调工具、看结果、调整路线，循环直到完成。自主性递增、可控性递减，落地要按场景选档位。

RAG vs 微调

都是给模型补它没有的知识，但路线相反。RAG 是开卷考试：回答时先去知识库检索相关资料，知识随时可更新、可溯源、成本低，私有知识库几乎都走这条。微调是背书：把知识/风格写进模型权重，改一次要重新训练，适合学语气、格式、领域套路。实际工程常组合：RAG 管知识，微调管风格。

开源 vs 闭源

开源（Llama、Qwen、DeepSeek）公开模型权重：可自己部署、可微调、数据不出内网，能力上限略低。闭源（GPT、Claude）只给 API：能力天花板最高，但看不见内部、数据要进对方云。企业选型的权衡轴基本就是"数据隐私/可控性 vs 顶级能力/省事"。

Token 与上下文窗口

模型不认字，文本要先切成 token（中文里 1 个字约等于 0.6～1 个 token）再计算，计费也按 token。上下文窗口是模型一次能"看见"的 token 总量上限：GPT-3 时代 4K，现在普遍 128K～1M。窗口越大能读越长的文档，但计算量和显存开销随之上涨——长文本是贵的。

参数量 · 稠密与 MoE

参数量 = 模型内部可调数字的个数，7B 即 70 亿个；一般参数越多越强，但也越慢越贵。稠密模型每次计算动用全部参数；MoE（混合专家）把模型拆成多个"专家"，每个请求只激活其中几个——总参数大（知识面广）、单次计算小（又快又省）。DeepSeek、Kimi、Qwen3 的大尺寸版本都是 MoE。

对齐：RLHF / DPO / GRPO

预训练后的模型只会"续写文字"，可能胡说、不听指令。对齐就是教它像人一样回答：RLHF = 训奖励模型打分 + 强化学习优化（ChatGPT 同款，贵且难）；DPO = 拿"哪个回答更好"的偏好对直接优化（简单，开源主流）；GRPO = 组内相对优势强化学习（DeepSeek-R1 训推理能力用的）。

量化：模型为什么能变小

把权重从 16 位浮点数压成 8/4 位整数：70B 模型从约 140GB 显存降到 35GB 左右，一张消费级显卡就能跑，代价是轻微精度损失。常见格式：GGUF（llama.cpp 生态，CPU 友好）、GPTQ/AWQ（GPU 生态）、FP8（新一代显卡原生）。你下的每个"Q4""Q8"模型就是不同量化档位。

L5 深度

基础模型层 · 五大家族

模型按处理的内容（模态）分成五个家族。每个家族都有自己的主流架构，且架构不是一步到位的——每一代算法都是在解决上一代的核心痛点。看懂这条迭代线，就看懂了 AI 技术演进的主干。

💬

语言模型（LLM）

架构：Transformer Decoder-only
原理一句话：把文本切成 token，让模型反复做「预测下一个 token」，读完全网语料后涌现出理解与生成能力。2017 年至今主干架构没变过，迭代发生在规模、训练范式和效率工程上。
算法迭代史
2017
Transformer 诞生（Google）
《Attention Is All You Need》提出自注意力机制，抛弃 RNN 的循环结构——任意两个 token 直接互相看，训练可以完全并行。这是之后一切的地基。
2018
GPT-1 vs BERT：两条路线分叉
GPT 走 decoder-only（单向、自回归生成），BERT 走 encoder-only（双向、适合理解）。后来生成式需求压倒一切，GPT 路线胜出，BERT 系退居搜索/分类等场景。
2019–2020
GPT-2 → GPT-3：规模定律（Scaling Law）
GPT-3 堆到 1750 亿参数，验证了「模型越大、数据越多、效果越好」的规律，并出现 few-shot 上下文学习——给几个例子就能做新任务，不用重新训练。
2022
ChatGPT：对齐革命（RLHF）
同样的模型，用人类反馈强化学习教它「说人话、听指令、不胡说」，从续写机器变成助手。架构没变，训练范式变了——这一步引爆大众市场。
2023
开源爆发 + MoE 普及
Meta LLaMA 开源点燃生态；Mixtral 带火 MoE 混合专家：模型切成多个"专家"，每次只激活几个——总参数大、单次计算小，性价比大增（DeepSeek、Kimi 后来都走这条路）。
2024
效率工程 + 推理模型元年
DeepSeek-V2 提出 MLA 多头潜在注意力，大幅压缩推理时的显存开销；OpenAI o1 用强化学习训练"慢思考"——模型先打草稿推理再作答，数学/编程能力跃升。
2025
推理模型开源 + 思考融合
DeepSeek-R1 用 GRPO 算法低成本训出推理能力并开源，震动业界；GPT-5、Claude 4 一代把「快回答/慢思考」合并为一个模型自动切换。
关键构件速览（现代 LLM 的零件表）
自注意力：每个 token 与全文其他 token 计算相关度，是"理解"的来源，但计算量随长度平方增长 · RoPE：旋转位置编码，让模型知道词序，且能外推到更长文本 · GQA：分组查询注意力，多个注意力头共享 KV，省显存 · MoE：混合专家，稀疏激活换性价比 · 上下文窗口：从 GPT-3 的 4K token 到现在普遍 128K～1M
🖼️

图像生成

架构：扩散模型 → DiT
原理一句话：扩散模型 = 训练时往图片上逐步加噪声直到全是噪点，再训练一个网络学会「去噪」；生成时从纯噪声出发，一步步去噪还原出图片。文本通过 CLIP 类编码器变成条件，引导去噪方向。
算法迭代史
2014
GAN 生成对抗网络
生成器造假图、判别器找茬，两者对抗进化。出图快但训练极不稳定、容易"模式崩溃"（只会画少数几种图），逐渐退出主流。
2020
DDPM 扩散模型
用「加噪-去噪」取代对抗训练，稳定且质量高，缺点是生成要迭代几十上百步，慢。
2021
CLIP + DALL·E
CLIP 用 4 亿图文对做对比学习，把图像和文本嵌入同一空间——从此可以用一句话精确控制生成内容，这是文生图的钥匙。
2022
Stable Diffusion：潜空间扩散
关键一步：不在原图上扩散，先把图压缩进潜空间（Latent Diffusion）再扩散，计算量降一个量级——消费级显卡也能跑，AI 绘画全民化。
2023
ControlNet 精确控制
给 SD 加"控制器"：用线稿、姿态、深度图约束构图，AI 绘画进入生产力场景。
2024
DiT 换掉 UNet + Flow Matching
骨干网络从 UNet 换成 DiT（Diffusion Transformer）——和 LLM 同款的 Transformer，吃下了 Scaling Law（越大越强）；采样目标从 DDPM 换成 Flow Matching（直接学从噪声到图像的"直线路径"，步数更少）。SD3、FLUX、Sora 全是 DiT。
🎬

视频生成

架构：时空潜空间扩散 + DiT
原理一句话：在图像扩散基础上加"时间维"——视频先被时空 VAE 压缩成一串时空 token，DiT 在这些 token 上做注意力，同时保证空间构图合理、时间上前后连贯。算力需求比图像高 1～2 个量级。
算法迭代史
2022
图像扩散硬扩时间维
Make-A-Video、Imagen Video：在图像模型上插入时间注意力层，让相邻帧互相参照。能生成几秒短片，但糊、闪、不连贯。
2023
视频扩散可用化
Stable Video Diffusion、Runway Gen-2：专门用视频数据训练，质量上一个台阶，但时长和一致性仍受限。
2024
Sora：时空 DiT + 世界模拟器
OpenAI 把视频统一成时空 patch token喂给 DiT，提出"视频模型是世界模拟器"的叙事；一分钟 1080p 长视频震撼业界。同年国产跟进：可灵（快手）、HunyuanVideo（腾讯）、Vidu。
2025
原生音效 + 物理一致性
Veo 3、Sora 2、可灵 2.x：生成带原生音轨（对话、环境音同步）、更长时长、物理规律更准（碰撞、流体、光影）。竞争焦点从"能不能生成"转向"像不像真实世界"。
和图像生成的三个本质区别：① 多一个时间维 → 需要时空 VAE 做更狠的压缩；② 注意力要同时管空间和时间（全 3D 注意力太贵，早期拆成"空间注意力+时间注意力"分开算）；③ 训练数据标注难——需要自动打标流水线给视频写描述。
🎙️

音频模型（语音识别 / 语音合成 / 音乐）

架构：Transformer + 音频编解码器
音频的共同思路：先用编码器把声波压成紧凑的 token 序列（如 EnCodec），之后就和语言模型一样用 Transformer 处理 token——"把声音当外语来建模"。
三条子线的迭代
ASR 语音识别
HMM → DNN → Whisper
早期靠隐马尔可夫模型+人工特征；2012 后深度学习接管；2022 年 OpenAI Whisper 用 68 万小时带噪数据弱监督训练 Transformer encoder-decoder，多语言、抗噪、免调优，成为事实标准。之后方向是流式实时（边说边出字）与多语种混合。
TTS 语音合成
拼接 → WaveNet → VITS → 大模型 TTS
最早从真人录音里拼接片段（机械感重）；2016 WaveNet 用神经网络逐采样点生成（逼真但极慢）；2021 VITS 端到端又快又好；2023 起 VALL-E 把 TTS 变成"语言建模"——给 3 秒参考音频就能克隆音色，CosyVoice、F5-TTS（Flow Matching）、GPT-SoVITS 都是这一代。
音乐生成
MusicGen → Suno / Udio
Meta MusicGen：Transformer 在音频 codec token 上自回归生成；商业产品 Suno/Udio 未公开细节（扩散与 Transformer 混合路线），已能按歌词+风格生成完整歌曲。
🧩

多模态模型

架构：视觉编码器 + LLM（或原生统一）
原理一句话：让语言模型"长眼睛"——视觉编码器（CLIP ViT）把图像切成视觉 token，投影层对齐后塞进 LLM，图和文在同一个空间里被理解。
算法迭代史
2021
CLIP 对齐图文空间
对比学习让"一张狗的图"和"a photo of a dog"的向量靠在一起——多模态的地基。
2023
LLaVA 范式：编码器 + 投影 + LLM
结构极简、训练便宜，成为开源多模态的模板（Qwen-VL、InternVL 等一大票）。同年 GPT-4V 证明闭源路线的上限。
2024–2025
原生全模态（Omni）
GPT-4o、Gemini：文本/图像/音频在同一个模型里端到端处理，不再是拼装——语音对话做到真人级延迟，看图、听音、读视频一体。
L4 深度

训练微调层 · 这些方式到底差在哪

训练一个能用的模型要走流水线：预训练（学知识）→ SFT 指令微调（学对话格式）→ 对齐（学人类偏好）。而 LoRA 那类是另一维度的选择——"改多少权重"。两个维度分开看就不乱了。

维度一：学习流水线（每个阶段解决什么问题）
阶段干什么数据成本谁做
预训练读海量文本做"预测下一个词"，灌入世界知识与语言能力万亿 token（全网语料清洗后）数百万美元起，千卡集群跑数月只有头部实验室做
SFT 指令微调用"问-答"样本教模型按指令对话，从续写器变助手几千～几十万条高质量对话1～8 张卡，几小时～几天企业/个人都能做
对齐（RLHF/DPO）用人类偏好数据教模型"什么样的回答更好"，压幻觉、立规矩人工标注的偏好对比对（A 比 B 好）RLHF 很高（见下），DPO 中等头部实验室为主
推理强化学习用可验证奖励（数学题对错、代码能否跑通）训练"慢思考"题目 + 自动判分，无需人工标注中高DeepSeek-R1、o1 的路线
对齐算法的三代迭代（这是最容易混淆的一组）

RLHF + PPO

2022 · ChatGPT 同款

先训一个奖励模型给回答打分，再用 PPO 强化学习优化。要同时维护 4 个模型（策略、参考、奖励、价值），工程复杂、训练不稳定、很贵。优点：上限高。

DPO

2023 · 直接偏好优化

数学上绕开奖励模型，直接用偏好对优化策略——少训一个模型、少一套强化学习基建，像 SFT 一样简单。如今开源社区对齐的主流选择。

GRPO

2024 · DeepSeek-R1 同款

组内相对优势：同一题采样一组回答，用组内平均分当基准算优劣，省掉价值模型。配合可验证奖励（数学/代码），是训练推理模型的当前最优解。

维度二：改多少权重（微调手段对比）
方式原理显存/成本适用场景
全参数微调所有权重都更新，效果上限最高极高（需存梯度+优化器状态，约为模型本身 4 倍显存）数据充足、要深度改造模型行为
LoRA冻结原模型，只训练旁路的低秩小矩阵（通常 <1% 参数）一张消费级显卡即可最常用：教模型新领域知识/风格/格式
QLoRA底座先量化到 4bit，再叠 LoRA更低，24GB 卡可微调 70B 模型显存紧张时的选择，精度略损
一句话决策：有千万预算才谈预训练；想改造现有模型的行为 → SFT + LoRA 起步；要模型更"像人" → DPO；要模型会"推理" → GRPO + 可验证奖励。
L6 深度

推理部署层 · 引擎之争

训练好的模型是"死"的权重文件，要跑起来服务才产生价值。推理的核心矛盾：生成是一个字一个字往外蹦的（自回归），天然慢且吃显存——所有引擎都在用各种手段对抗这件事。

五大引擎对比（这是"这几个有什么区别"的答案）
引擎定位硬件绝活适合谁
vLLM服务端高吞吐推理的事实标准NVIDIA GPU（也支持 AMD/昇腾）PagedAttention：像操作系统管理内存页一样管理 KV 缓存，显存浪费降到极低；连续批处理生产环境 API 服务
SGLang新一代高性能引擎NVIDIA GPURadixAttention 前缀缓存：相同上下文不重复计算；结构化输出（JSON）极快Agent、复杂调用链、高并发
llama.cpp极限可移植的 C++ 引擎CPU / Mac / 消费级显卡 / 甚至手机GGUF 量化格式，无 Python 依赖，任何设备都能跑本地、边缘、没有数据中心 GPU 的场景
Ollama本地跑模型的"一键方案"同 llama.cpp（底层就是它）一条命令拉模型、起服务，极简个人开发者、快速试验
TensorRT-LLMNVIDIA 官方极致性能仅 NVIDIA深度编译优化，单卡性能天花板，但配置繁琐追求极限、愿意折腾的团队
引擎背后的关键技术（名词拆解）

量化

省显存的第一手段

权重从 16 位浮点压到 8/4 位整数，显存直接砍半再砍半，代价是轻微精度损失。格式：GGUF（llama.cpp 系，CPU 友好）、GPTQ/AWQ（GPU 系）、FP8（新一代 GPU 原生）。

KV 缓存

自回归的代价

生成每个新 token 都要回看前文，把中间结果（KV）缓存起来才能不重算。它是推理显存的大头——vLLM 的 PagedAttention、DeepSeek 的 MLA 都是在治它。

连续批处理

吞吐的关键

不等一批请求全做完，谁生成完谁出列、新请求随时插队——GPU 利用率拉满。vLLM/SGLang/TGI 的标配。

投机解码

加速单请求

小模型先快速"猜"几个 token，大模型一次性并行验证——猜中就白赚。单用户延迟可降 2～3 倍。

PD 分离

2024 起的新架构

推理分两阶段：预填充（读输入，算力密集）和解码（逐字生成，显存带宽密集）。两阶段拆到不同机器池分别优化，是大规模服务的新趋势。

L2 深度

算力层 · 芯片分类与路线之争

芯片不是一种东西——按用途分成四类，差别比想象的大；而"谁能造出好用的 AI 芯片"目前有四条半路线，生态差距才是真正的护城河。

芯片按用途分四类（"做渲染的、做训练的、做推理的"都在这）
类型设计目标特征代表
训练芯片喂饱千卡集群的极限算力高精度（BF16/FP8）、超大 HBM 显存与带宽、NVLink 高速互联、单卡上千瓦；要跑前向+反向+梯度同步，最贵最难H100 / H200 / B200、昇腾 910B/910C、TPU v5p
推理芯片单位成本出最多 token只跑前向，可以用低精度（INT8/INT4），不追求极致互联，强调性价比与能效；很多是专用 ASICNVIDIA L4/L40S、昇腾 310、Groq LPU、各类国产推理卡
渲染芯片（显卡）图形渲染：游戏、影视、3D光栅化管线 + RT Core 光线追踪 + 显示输出；因带 CUDA 和张量核，也常被"兼职"跑中小 AI 模型GeForce RTX 系列、AMD Radeon、摩尔线程（国产渲染卡）
边缘芯片终端设备上的低功耗 AINPU 形态，几瓦功耗跑量化小模型：拍照优化、语音唤醒、端侧助手苹果 Neural Engine、高通 Hexagon、NVIDIA Jetson
训练卡 vs 渲染卡的一个直观区别：H100 这类计算卡没有显示输出接口——它不为画面而生，晶体管全花在张量计算和显存带宽上；而 RTX 显卡要分相当面积给光栅化、光追和显示管线。

L1 深度

能源层 · AI 的物理底座

再往下一层就不是代码了：AI 数据中心首先是"电老虎"，其次才是机房。模型规模的每一次跃升，最终都折算成电表上的数字——电力正在取代芯片成为 AI 扩张的第一瓶颈。

一度电怎么走到 GPU（供电链路）
电网高压电 → 变电站降压 → 数据中心配电室 → UPS 不间断电源（电池兜底，断电瞬间接管）→ 柴油发电机（长时间断电备份）→ PDU 配电柜 → 每个机柜 → 每张 GPU。任何一环断电，训练中断的代价以小时计。
散热：从空调到液冷

风冷

传统方式

空调冷风 + 风扇散热。单机柜功率 10kW 以内够用，风扇本身也耗电。老数据中心都是这个。

冷板液冷

GB200 时代的标配

冷却液直接接触芯片冷板带走热量。NVIDIA GB200 NVL72 单柜约 120kW（≈60 户家庭用电），风冷物理上已经吹不动，液冷成为强制选项。

浸没式液冷

更激进的方向

整台服务器泡进绝缘冷却液。换热效率最高，但运维方式完全改变，目前小规模商用。

为什么说电力是新瓶颈：Sam Altman 等公开说过，芯片之后卡脖子的是电。数据中心选址开始跟着电站走，科技巨头直接下场买电——微软签了重启三里岛核电站的 20 年购电协议，亚马逊、谷歌收购核电初创（小型模块化反应堆 SMR）。PUE（总能耗/IT 设备能耗，越接近 1 越好）成为衡量数据中心水平的核心指标。
